SHIL V25.2 STAGE 1 - گزارش تغییرات
=================================

مبنای این نسخه: SHIL V25.1 BETA FREEZE
هدف: اجرای کامل سه تغییر تاییدشده، بدون ورود به سایر ایرادات.

1) بانک مصرف‌کننده‌ها و بارهای پروژه
-----------------------------------
- بانک 250 تایی حفظ شده است.
- دسته‌بندی تصادفی قدیمی بانک پایه حذف و دسته‌بندی معنایی بر اساس نوع مصرف اعمال شد.
- دسته‌های اصلی: سرمایش، گرمایش، روشنایی، صوتی و تصویری، آشپزخانه، لوازم خانگی، اداری، شبکه و مخابرات، امنیتی، پمپ و موتور، صنعتی و کارگاهی، کشاورزی، درمانی، فروشگاهی و متفرقه.
- رکورد سفارشی ادمین دسته انتخابی خودش را حفظ می‌کند.
- دسته ناشناخته به «متفرقه» منتقل می‌شود.
- در کارتابل ادمین همه دسته‌ها به صورت Accordion و در شروع بسته هستند.
- دکمه «افزودن مصرف‌کننده» در بالای بانک باقی مانده و برای رسیدن به آن اسکرول طولانی لازم نیست.
- در مسیر پروژه کاربر نیز تجهیزات بر اساس همین دسته‌ها و به صورت Accordion بسته نمایش داده می‌شوند.
- جستجو روی بانک پویا و Cloud همچنان فعال است.

2) بانک تجهیزات فنی ادمین
-------------------------
- پنل خورشیدی، اینورتر خورشیدی، باتری، برق اضطراری و تجهیزات حفاظتی در شروع بسته هستند.
- داخل هر بانک، زیرگروه‌های فنی نیز Accordion بسته دارند.
- اینورترها به صورت پیش‌فرض با نوع آفگرید/هیبرید/آنگرید گروه‌بندی می‌شوند.
- باتری‌ها با شیمی باتری گروه‌بندی می‌شوند.
- حفاظت با حوزه خورشیدی/برق اضطراری/مشترک گروه‌بندی می‌شود.
- ادمین می‌تواند «دسته / زیرگروه» اختصاصی تعریف کند.
- انتخاب نوع تجهیز و دکمه «افزودن تجهیز» به بالای CMS منتقل شده است؛ نیازی به اسکرول تا انتهای بانک نیست.

3) ورود کاربر و ادمین
---------------------
- گزینه «مرا به خاطر بسپار» اضافه شد.
- ایمیل آخرین حساب فقط در صورت فعال بودن این گزینه روی همان دستگاه نگهداری می‌شود.
- رمز عبور خام در LocalStorage ذخیره نمی‌شود.
- فیلدها دارای name/autocomplete استاندارد هستند تا Password Manager مرورگر/PWA رمز را ذخیره و پیشنهاد کند.
- Logout همچنان Session را می‌بندد و ذخیره ایمیل به معنی بازماندن دسترسی نیست.

4) مدیریت پروژه‌های ادمین
-------------------------
- پروژه‌ها بر اساس updatedAt/completedAt/lastVisitedAt/createdAt مرتب می‌شوند و جدیدترین پروژه اول است.
- همه پروژه‌ها در شروع Accordion بسته هستند.
- روی کارت بسته فقط نام کاربر و مسیر پروژه نمایش داده می‌شود:
  * مسیر اجرای پنل خورشیدی
  * مسیر اجرای برق اضطراری
- با باز کردن کارت، جزئیات پروژه، شرایط محیطی، ورودی‌ها، تنظیمات، چکیده، نتایج و تحلیل هوشمند در صورت وجود نمایش داده می‌شوند.
- سه عملیات اصلی در انتهای پروژه:
  1. حذف پروژه
  2. انتقال به سناریوهای آماده
  3. اشتراک‌گذاری
- حذف پروژه دارای Confirm برای جلوگیری از حذف تصادفی است.

5) انتقال پروژه به سناریوهای آماده
---------------------------------
- پروژه خورشیدی به ready_scenarios با domain=solar منتقل می‌شود.
- پروژه برق اضطراری به ready_scenarios با domain=emergency منتقل می‌شود.
- سطح سناریو بر اساس توان تقریبی پروژه سبک/متوسط/سنگین تعیین می‌شود.
- سناریو شامل Source Project، مشخصات کلیدی، توان/انرژی، تجهیزات پیشنهادی و اطلاعات نهایی پروژه است.
- سناریوهای واقعی تاییدشده در ابتدای لیست سناریوهای آماده کاربر قرار می‌گیرند و Badge «پروژه واقعی تاییدشده» دارند.
- برای فعال شدن خواندن این بانک در Supabase باید فایل زیر یک بار در SQL Editor اجرا شود:
  supabase/SHIL_V25_2_STAGE1_READY_SCENARIOS.sql

6) دریافت / اشتراک‌گذاری پروژه
------------------------------
- دکمه «اشتراک‌گذاری» ابتدا دو انتخاب نشان می‌دهد:
  * ذخیره PDF
  * انتقال / اشتراک
- PDF از محتوای کامل پروژه ساخته می‌شود.
- Export جدید Multi-page است؛ بنابراین گزارش بلند به یک صفحه بریده نمی‌شود.
- در زمان ساخت PDF تمام Detailsهای داخلی برای خروجی باز می‌شوند تا دیتای کامل در گزارش قرار بگیرد.
- انتقال از Web Share API دستگاه استفاده می‌کند و اگر Share فایل پشتیبانی نشود PDF دانلود می‌شود.

7) QA انجام‌شده در محیط ساخت
-----------------------------
- Node syntax check برای فایل‌های JS جدید/تغییرکرده: PASS
- TypeScript parser با JSX روی صفحات تغییرکرده: PASS
- Static gate اختصاصی V25.2 Stage 1: PASS
- 15 کنترل معماری Stage 1 پاس شد.

Build کامل Vite در محیط ساخت به دلیل کامل نشدن npm ci در محدودیت محیط اجرا نشد؛ روی سیستم پروژه بعد از نصب Patch حتما npm run build اجرا شود.

دستورات تست:
 npm ci
 npm run v25.2:check
 npm run build
 npm run dev -- --host

نکته مهم:
قبل از تست «انتقال پروژه به سناریوهای آماده» SQL migration جدید را در Supabase اجرا کنید.
